# Настройки и автоматизация

Все пункты ниже — `Настройки` в главном меню, доступны только сотрудникам
с достаточными правами (обычно ADMIN, иногда MANAGER — зависит от роли и
конкретной настройки).

## Юрлица, статусы документов, валюта

- **Юрлица** — реквизиты вашей компании, см. [Первые шаги](01-getting-started.md).
- **Статусы документов** — список возможных статусов для каждого типа
  документа (Заказ, Заказ поставщику, Счёт и т.д.) и переходы между ними —
  см. «Бизнес-процессы» ниже, это тот же механизм.
- **Валюта** — базовая валюта организации и курсы для операций в других
  валютах.

## Доп. поля

Если стандартных полей не хватает (например, нужно поле «Менеджер по
рекламации» на заказе, которого нет в системе по умолчанию) — заведите
дополнительное поле нужного типа (текст, число, дата, ссылка на
справочник, чекбокс и т.п.) для нужного типа документа/сущности. После
этого поле появится на форме создания/редактирования.

## Справочники

Если вам нужен свой собственный список значений для выбора (не товары,
не клиенты — что-то специфичное для вашего бизнеса, например «Каналы
рекламы» или «Причины отказа») — заведите пользовательский справочник
здесь, а затем используйте его как источник значений для доп. поля.

## Статьи расходов

Простой список категорий расходов (например, «Аренда», «Зарплата»,
«Хозрасходы») — используется при создании расходного кассового ордера
(см. ниже), чтобы категоризировать, на что ушли деньги.

## Кассовые ордера

Отдельно от обычных `Платежи` (которые всегда привязаны к заказу/счёту) —
кассовые ордера для операций без привязки к конкретному документу: взнос
учредителя, хозяйственные расходы, инкассация. Приходный или расходный,
для расходного — можно указать статью расходов. Контрагент необязателен (в
отличие от обычного платежа).

## Корректировки баланса

Если баланс взаиморасчётов с клиентом нужно поправить вручную (простить
долг, перенести начальное сальдо при переходе с другой учётной системы) —
на карточке клиента доступна ручная корректировка с указанием, какую
именно сторону баланса она затрагивает (как с покупателем или как с
поставщиком).

## Роли доступа

Помимо базовых ролей (ADMIN/MANAGER/EMPLOYEE/CASHIER/PRODUCTION — см.
[Первые шаги](01-getting-started.md)) можно создать **кастомную роль** с
точной настройкой прав (просмотр/создание/редактирование/удаление) по
каждому разделу отдельно — например, «Менеджер по продажам без доступа к
финансам». Кастомную роль можно назначить как нескольким сотрудникам
(переиспользуемая роль), так и одному конкретному (индивидуальные права).

## Отделы

Группировка сотрудников (`Настройки → Отделы`) — используется для
области видимости «свой отдел» в правах (сотрудник видит только документы
своего отдела) и как один из способов назначить, кто может выполнять
конкретный переход статуса документа (см. ниже).

## Бизнес-процессы

У каждого типа документа (Заказы, Заказы поставщику и т.д.) — своя кнопка
«Бизнес-процессы» в тулбаре списка. Здесь настраивается:

- в каких статусах можно **создать** новый документ этого типа, и кто
  именно (по сотруднику/отделу/роли);
- переходы между статусами — каждое правило: из каких статусов, в какие
  статусы, и кто может выполнить именно этот переход.

Если сотрудник не видит нужный статус в выпадающем списке — это, скорее
всего, означает, что ему не разрешён именно этот переход, а не ошибку.

## Сценарии-автоматизации

`Настройки → Сценарии` — правила «если произошло событие с документом —
сделать действие автоматически», без участия человека. Например: «когда
заказ поставщику переходит в статус Оплачен — автоматически создать счёт
входящий» или «когда заказ создан — отправить уведомление ответственному
сотруднику». Несколько сценариев включены по умолчанию (уведомления на
создание/оплату основных типов документов) — их можно отключить или
изменить, как и создать свои. У сценария: событие (документ + создан/
изменён), необязательные условия (сузить, когда сценарий срабатывает), одно
или несколько действий (создать связанный документ, отправить внутреннее
уведомление, отправить вебхук).

## Вебхуки

`Настройки → Вебхуки` — если вам нужно, чтобы внешняя система (сайт, другой
сервис) узнавала о событиях в этой системе автоматически (не через
периодический опрос API) — заведите вебхук на нужное событие с адресом
внешнего обработчика. При срабатывании система отправит туда POST-запрос с
данными события; если внешняя система была недоступна — будет несколько
повторных попыток. История доставок видна там же.

## API-ключи

`Настройки → API-ключи` — если вам нужно подключить внешнюю систему (1С,
BI-инструмент, собственный скрипт), которая сама будет запрашивать данные —
создайте ключ здесь. Ключ показывается только один раз в момент создания —
сохраните его сразу, восстановить забытый ключ нельзя, только отозвать и
выпустить новый. Подробности использования — техническая документация
`docs/handbook/api/`, это отдельный раздел для разработчиков.

## Журнал изменений

`Настройки → Журнал изменений` — кто, что и когда изменил. Надёжно
фиксируются изменения, сделанные через API-ключи; изменения из обычного
интерфейса в текущей версии в журнал не попадают — это известное
ограничение, не ошибка отображения.

## Импорт

`Настройки → Импорт` — загрузка каталога товаров или клиентов из Excel/CSV
файла: загрузите файл, сопоставьте колонки файла с полями системы,
запустите импорт. Строки, которые не удалось импортировать (например,
из-за отсутствия обязательного поля), можно скачать отдельным файлом
для исправления и повторной попытки.
