# Ошибки, пагинация, фильтрация, лимиты

## Формат ошибки

```json
{ "errors": [{ "error": "Текст ошибки на русском", "parameter": "имя_поля" }] }
```

HTTP-коды: `400` некорректный запрос (в т.ч. невалидный `filter`/`order`/
`expand`), `401` нет/неверный/отозванный ключ, `404` сущность или запись не
найдена, `405` операция не поддерживается для этого типа (документы — см.
`README.md`), `409` конфликт (нарушение уникальности/внешнего ключа), `412`
не хватает обязательного поля, `429` превышен rate limit.

Это **свой** компактный набор кодов, не копия числового каталога МойСклад
(1000–15000+) — их коды рассчитаны на их собственных клиентов конкретной
версии их API, копировать 1:1 не имеет смысла.

## Пагинация

`limit` (по умолчанию 100, максимум 1000), `offset`. Ответ на список несёт
`meta.size` (сколько всего строк с учётом фильтра), `meta.nextHref`/
`meta.previousHref` (уже готовые ссылки на следующую/предыдущую страницу,
`null` если страницы нет).

## Фильтрация

```
?filter=status=ACTIVE
?filter=status=ACTIVE;unitPrice>100
```
`;` — И (AND) между условиями. Операторы: `=`, `>`, `<`, `>=`, `<=`.
**Сознательно уже, чем у МойСклад** — нет `!=`, нет операторов подстроки
(`~`), нет ИЛИ-групп. Фильтровать можно только по полям из списка
`entities.md` для этого типа (не по связанным сущностям).

## Поиск

```
?search=Ромашка
```
Регистронезависимый `contains` по полям из колонки «Поиск» в `entities.md`
(если для типа не заданы поисковые поля — 400 «Поиск недоступен»).

## Сортировка

```
?order=name,asc
?order=status,asc;createdAt,desc
```

## Раскрытие связей (`expand`)

```
?expand=client
?expand=client,lineItems
```
Только связи, явно перечисленные в `entities.md` для конкретного типа —
запрос неразрешённой связи возвращает 400, а не молча игнорируется.

## Rate limiting

45 запросов / 3 секунды **на один API-ключ** — свой in-memory sliding
window (`src/lib/api-rate-limit.ts`), без Redis. Каждый ответ несёт
заголовки:

```
X-RateLimit-Limit: 45
X-RateLimit-Remaining: 12
```

При превышении — `429` с `X-RateLimit-Remaining: 0`. **Важная оговорка**:
лимитер живёт в памяти одного процесса Node — если приложение развёрнуто
несколькими инстансами за балансировщиком, лимит фактически умножается на
число инстансов (каждый считает независимо). Для одного dev/small-prod
процесса — ограничение работает как задумано. Переход на общий (Redis-based)
лимитер — пункт для будущей доработки, если проект перейдёт на несколько
инстансов.

## Примеры `curl`

```bash
# Список клиентов, отсортированный по имени
curl -H "Authorization: Bearer $API_KEY" \
  "https://ваш-домен/api/v1/entity/client?order=name,asc&limit=20"

# Создать клиента
curl -X POST -H "Authorization: Bearer $API_KEY" -H "Content-Type: application/json" \
  -d '{"name": "ООО Ромашка", "inn": "7700000000"}' \
  "https://ваш-домен/api/v1/entity/client"

# Обновить телефон клиента (частично — остальные поля не тронуты)
curl -X PUT -H "Authorization: Bearer $API_KEY" -H "Content-Type: application/json" \
  -d '{"phone": "+79990001122"}' \
  "https://ваш-домен/api/v1/entity/client/abc123"

# Отозванный/неверный ключ
curl -H "Authorization: Bearer неверный_ключ" "https://ваш-домен/api/v1/entity/client"
# → 401 {"errors":[{"error":"Неверный или отозванный API-ключ"}]}
```
