# Select показывает сырое значение

Реальный UI-баг, найденный только благодаря подключённому браузерному инструменту (Playwright MCP) — до этого несколько фаз разработки прошли "вслепую" (без визуальной проверки).

## Симптом

Выпадающий список (`<Select>` из shadcn на базе Base UI) после выбора значения показывал пользователю сырое value ("PRODUCT", "__none__") вместо человекочитаемой подписи ("Товар", "—").

## Причина

`@base-ui/react`'s `<Select.Value>` по умолчанию рендерит именно `value`, а не текст соответствующего `<SelectItem>`. Нужен явный проп `items` (карта `value → label`) на `<Select.Root>`, иначе компонент физически не знает, как сопоставить значение с подписью — это не баг конкретной реализации, а особенность API, которую легко пропустить, придя с опыта Radix (где `SelectValue` просто клонирует children выбранного айтема).

## Где встречалось (на момент фикса)

`catalog-item-form.tsx` (тип товара, единица измерения), `catalog-group-form.tsx` (родительская группа) — тянулось с Phase 4, просто не было видно без браузера.

## Фикс

Передавать `items={{ ЗНАЧЕНИЕ: "Подпись", ... }}` на каждый `<Select>`, где используется управляемое/дефолтное значение. Смотреть по коду: везде, где создаётся новый `<Select>` с `defaultValue`/`value` — проверить, есть ли `items`.

## Урок

Без визуальной проверки в реальном браузере такие баги невидимы для сборки/тайпчека — TypeScript и `npm run build` ничего не подсвечивают, это чисто рантайм-визуальная проблема. См. также [[Стек и структура#Особенности Base UI]].
