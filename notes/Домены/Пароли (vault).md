# Пароли (vault)

Самый чувствительный домен проекта — идея пользователя поверх МойСклад (аналога в оригинале нет). Менеджер паролей: сотрудники ↔ доступ к сервисам ↔ теги ↔ аудит-лог.

## Шифрование — двухуровневая схема

- `ENCRYPTION_MASTER_KEY` (из `.env`, 32 байта) — мастер-ключ приложения
- Оборачивает случайный per-org DEK (`Organization.encDekWrapped/encDekNonce`) — см. [[Мультитенантность]]
- Каждый секрет (`VaultServiceEntry.ciphertext/nonce/authTag`) шифруется собственным случайным nonce на DEK организации, AES-256-GCM
- `authTag` проверяется при расшифровке — подмена шифротекста/тега/чужой ключ → исключение, не тихий проглот

`src/lib/crypto.ts` (примитивы) + `src/lib/org-dek.ts` (`getOrgDek` с ленивым бэкфиллом DEK для организаций, заведённых до появления этого домена).

## Авто-теги по доступу

`EmployeeVaultAccess` (join сотрудник↔запись) → лениво создаёт/переиспользует `Tag` (`kind: EMPLOYEE_ACCESS`) на сотрудника. Отзыв доступа с одной записи не трогает тег, если он используется на другой.

## Доступ — гейтинг на уровне маршрута, не только UI

`can(ctx.role, "vault", "read")` → `notFound()` для `EMPLOYEE`, не просто скрытие пункта меню (см. [[Ролевая модель]]). Прямой заход по URL тоже заблокирован.

## Аудит

`revealVaultSecret` — отдельное действие от обычного открытия карточки, пишет строку в `VaultAccessLog` при каждом раскрытии пароля.

## Поиск

Пароли **намеренно исключены** из общего поиска (`CommandPalette`) — чтобы не утекали названия/теги сервисов через общий поиск для ролей с более широким доступом к поиску, чем к vault.
